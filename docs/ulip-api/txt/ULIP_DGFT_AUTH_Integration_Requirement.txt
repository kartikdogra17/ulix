Introduction 
1.1 Purpose 
 
The purpose of this document is to define and provide details for authenticating DGFT Response 
data with respect to IEC Number, Organization number, PAN, issue date which we have received 
from DGFT system. 
This document details the following points: 
 
1. Data Integration and verification between DGFT and ULIP web service: Identification 
of operational points where data integration and verification between DGFT and ULIP web 
service will be needed. 
 
2. Technical Approach for performing Data Integration  
 
The Overall Description 
 
User will share the information such as iec number (which is mandatory field) and date of 
birth and will at least share either organization number, pan or issue date based on data 
send by user ULIP system will call respective DGFT API for accessing information and then 
verify data based on user input. 
 
Following are the point for accessing vehicle information: - 
 
1. This API will share iec number data based on information provided by user. 
 
2. ULIP will expose API for getting data from DGFT API and then verify the response if 
correct information is there or not in the response which we are getting from DGFT API. 
 
3. AUTHAPI/01 API will take iec number (Which is mandatory field) and will share at least 
one of the field either organization number, pan or issue date from user and get data 
from DGFT API and then will verify if correct organization number, pan or issue date is 
coming from DGFT API response or not. 
 
1.2 Data Integration between DGFT System and ULIP application 
 
User will share information to ULIP system based on data shared ULIP will verify the data for 
the user. 
1.3 AUTHAPI/01 
 
This API will take iec code data and connect with DGFT API to get data.

1.3.1 Technical Approach  
1. All the data will be shared through rest web services. 
2. ULIP system will provide iec number and will at least share either organization name 
, pan or issueDate for which detail and verification needs to be done. 
3. DGFT API will share details of iec information which exist in DGFT system in JSON format. 
4. ULIP system will verify the response which is received from DGFT API based on the 
organization name , pan or issueDate which is provided by the user. 
 
5. ULIP system will provide the data in JSON Object format in response body. 
 
Example: 
 
Iec Number AFAPT1958B, organization name  VIBGYOR FASHION AND BOUTIQUE , pan  
A*A*T*9*8* and  issueDate 26-07-2020 is shared by ULIP system, then DGFT-Auth integration 
will make a request to DGFT API.

1.4 Data Transmission & Authentication Mechanism 
 
All data exchange would be done over secure HTTP (HTTPS). Request from ULIP's system would 
be made in SARATHI system through a data exchange URL that has following form: 
 
For production - 
https://www.ulip.dpiit.gov.in/ulip/v1.0.0/AUTHAPI/01 
 
Body:  
 
  
{ "iecnumber": "AFAPT1958B", 
    "PAN": "AFAPT1958B", 
    "Organization name": "VIBGYOR FASHION AND BOUTIQUE", 
    "Issue date": "Jul 26, 2020 10:20:46 AM" 
} 
 
Access to above data exchange URL would be authorized by use of a security mechanism 
implemented by the ULIP system. It is as follows: 
 
 First time access: It would require a username and password [which would be shared with 
user beforehand].  Once user hit with valid user id and password, ULIP system will return a 
basic authorization token to user, using that token user will communicate with ULIP system 
until token will not get expired.
