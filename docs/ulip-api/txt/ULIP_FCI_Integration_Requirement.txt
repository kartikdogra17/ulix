Introduction 
1.1 Purpose 
 
The purpose of this document is to define and provide details for accessing API for FCI 
system information from ULIP system. 
This document details the following points: 
 
1. Data Integration between FCI and ULIP web service: Identification of operational points 
where data integration between FCI and ULIP web service will be needed. 
 
2. Technical Approach for performing Data Integration  
 
The Overall Description 
 
Users will just hit the API and get the data (no need to share any data in the request 
bocy). ULIP system will call respective FCI API for accessing information. 
 
Following are the points for accessing vehicle information: - 
 
1. This API will share the vehicle information data to the user. 
 
2. ULIP will expose API to get data from FCI API. 
 
3. FCI/01 API will take no data in request body from user and get data from FCI API. 
1.2 Data Integration between FCI System and ULIP application 
 
Users will share information to ULIP system based on data shared ULIP will provide 
data to user. 
1.3 FCI/01 
 
This API will connect with FCI API to get data.

1.3.1 Technical Approach  
1. All the data will be shared through rest web services. 
2. ULIP system will provide detail is required. 
3. FCI API will share details of FCI vehicle information which exist in FCI system in JSON 
format. 
4. FCI Integration will add JSON in response key in response body. 
5. ULIP system will provide the data in JSON Object format in response body. 
 
Example: Data is shared by ULIP system, then FCI-integration will make a request to 
FCI API. 
 
Request: The request must be of the following format and passed within the URL body in 
JSON format.

1.4 Data Transmission & Authentication Mechanism 
 
All data exchange would be done over secure HTTP (HTTPS). Request from ULIP's system would 
be made in FCI system through a data exchange URL that has following form: 
 
For staging: https://www.ulipstaging.dpiit.gov.in/ulip/v1.0.0/FCI/01 
 
{}

Access to above data exchange URL would be authorized by use of a security mechanism 
implemented by the ULIP system. It is as follows: 
 
• First time access:  It would require a username and password [which would be shared with 
user beforehand].  Once user hit with valid user id and password, ULIP system will return a 
basic authorization token to  user, using that token user will communicate with ULIP system 
until token will not get expired. 
 
Summary of HTTP Basic Authentication is as follows: 
 
First time User hits ULIP secured API through username and password for access token as follow- 
 
curl --location --request POST 
'https://www.ulipstaging.dpiit.gov.in/ulip/v1.0.0/user/login' \ 
--header 'Accept: application/json' \ 
--header 'Content-Type: application/json' \ 
--data-raw '{"username": "xxxx","password": "xxxx@123"}'

Upon successful authentication, the user would be logged into the ULIP system and get an access 
token. Though this token user can communicate with ULIP. This token has expiry time which 
represents user session. The session time out for the same to be fixed hour, generally it is for 30 
minutes. If there is no request coming from user for 30 minutes, then session (token) will be 
expired, and user need to re authenticate.
